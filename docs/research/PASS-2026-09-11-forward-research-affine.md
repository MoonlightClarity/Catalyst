# Forward comparator pass — AFFiNE / BlockSuite — 2026-09-11

Status: source/documentation research only; no Catalyst GUI manipulation or product code.

## Why AFFiNE is a useful comparator

AFFiNE is relevant because it is not merely a note app with a canvas bolted on. Its editor framework, BlockSuite, is explicitly designed around one source of knowledge rendered through different editor modes. The upstream project describes PageEditor and EdgelessEditor as sharing the same rich-text capabilities and states that documents can be reused in multiple editors.

Current stable AFFiNE release visible upstream during this pass is 0.27.4 (released 2026-08-18); 0.27.5 is still beta while daily canary builds continue. This pass therefore treats 0.27.4-era architecture as current stable, while using current BlockSuite documentation for the editor/data model.

## Mechanism 1 — Page and Edgeless are isomorphic portrayals, not converted copies

BlockSuite documentation states that documents in Edgeless mode are isomorphic to those in Page mode and that no data conversion occurs during mode switching.

That is a strong implementation precedent for Catalyst's rule that a change of portrayal should not manufacture a second analytical object or require lossy conversion.

A single document can be scheduled/reused across multiple editor instances, while PageEditor and EdgelessEditor provide different interaction/rendering environments over the same underlying document state.

## Mechanism 2 — content hierarchy and canvas hierarchy are deliberately different

BlockSuite does not treat the whiteboard as a flat list of generic cards. Rich-text content remains a block tree. Edgeless-specific graphical content lives in a Surface Block, with brush, shape, and connector entities represented as SurfaceElements.

Some blocks can live directly under the Surface Block and become freely placeable, while blocks nested inside notes retain document-flow layout. This means spatial freedom is attached to placement context rather than being an intrinsic property of every content object.

Catalyst implication: placement state should be modeled independently enough that an object can participate in a spatial Working Picture without forcing all analytical content into one universal canvas-card ontology.

This also reinforces the need to distinguish at least:
- analytical/content identity;
- structural containment or document membership;
- spatial occurrence/geometry;
- surface-only graphical/portrayal artifacts.

## Mechanism 3 — geometry and z-order are first-class portrayal state

Indexable blocks and surface elements carry `xywh` geometry for absolute canvas placement and an `index` used for whiteboard hierarchy/z-order via fractional indexing.

The important Catalyst lesson is not the exact field design. It is that authored geometry and display ordering deserve explicit state rather than being reconstructed opportunistically from semantic links or tree order.

This supports Catalyst's emerging rule that authored analytical geography should survive mode/view changes and should not be regenerated by automatic layout.

## Mechanism 4 — frames and groups encode different association semantics

BlockSuite's Edgeless model has two association mechanisms that are cognitively distinct:

- Frames have explicit spatial bounds; moving the frame moves content currently within its geometric area. Association is therefore region/geometry based.
- Groups store child node IDs and can nest. Association is therefore explicit membership rather than mere proximity.

This distinction is unusually relevant to Catalyst. It demonstrates in a production editor architecture that spatial enclosure and explicit membership do not have to be collapsed into one generic `group` operation.

Catalyst should go further than AFFiNE by keeping provisional geometry, explicit organizational membership, branch structure, and analytical semantic relations inspectably distinct.

## Mechanism 5 — mode interoperability exposes a caution

AFFiNE/BlockSuite's isomorphism is powerful, but the whiteboard still requires special surface storage and mode-specific visibility rules. Earlier BlockSuite interoperability work explicitly dealt with deciding which top-level edgeless objects should also be visible in document mode.

This means "same underlying document" does not automatically solve representation semantics. Catalyst will still need explicit policy for which occurrences/portrayals appear in which projection and which state belongs to identity versus a particular view.

The useful inheritance is shared identity across portrayals. The dangerous inheritance would be assuming every representation should expose every object or that document hierarchy is the canonical semantic hierarchy.

## Local-first implementation relevance

AFFiNE currently presents itself as local-first and collaborative. Its ecosystem uses BlockSuite/Yjs-derived CRDT document state; the associated OctoBase project describes offline-available storage, schemaless structured/unstructured/rich-text data, binary storage, full-text indexing, and CRDT-driven synchronization.

This is implementation evidence that rich document state, canvas state, and collaboration can live above a local-first persistence substrate rather than requiring a cloud-authoritative application model.

Catalyst should not copy this stack wholesale. Its requirement is a non-proprietary, maintainable analytical record with strong provenance and durable local use; CRDT complexity should be justified only if collaboration/offline concurrency actually requires it.

A caution from current AFFiNE issue history: local-first behavior is not automatically uniform across every client surface. A 2025 mobile issue reports cloud workspaces unavailable when the server is down. Therefore Catalyst should test offline guarantees per client/workflow rather than accepting a product-level `local-first` label as sufficient evidence.

## What Catalyst should inherit

1. One durable content identity can support materially different editors/portrayals without conversion.
2. Spatial geometry can be explicit portrayal state rather than derived from semantic structure.
3. Document-flow containment and free-canvas placement can coexist in one record.
4. Geometric framing and explicit grouping can be separate association mechanisms.
5. View-specific visibility is legitimate and should be policy-driven rather than treated as duplication.
6. Editor infrastructure can be separated from application shell, reducing pressure to make UI architecture dictate the data model.

## What Catalyst should not inherit

1. A universal block ontology simply because it simplifies editor reuse.
2. Treating page/document tree position as the canonical analytical structure.
3. Letting surface-mode implementation constraints silently create semantic hierarchy.
4. Assuming a shared underlying document means every portrayal should expose the same objects in the same way.
5. Importing a CRDT/local-first stack before Catalyst has a concrete collaboration requirement that warrants its complexity.
6. A generic whiteboard grouping model in place of Catalyst's stronger distinction among placement, organization, provenance, inference, and world relations.

## Net architectural effect

AFFiNE strengthens the current Catalyst architecture but sharpens its data-model boundary.

The strongest transferable idea is not "merge notes and whiteboard." It is **shared identity with portrayal-specific state**.

A Catalyst analytical object should be able to remain itself while appearing in a document-like projection, a spatial Working Picture, a branch/outline projection, or another analytical lens. But each occurrence may need its own placement/visibility/focus state, and those portrayal states must not masquerade as analytical truth.

AFFiNE also offers a concrete precedent for keeping geometry-based association distinct from ID-based membership. Catalyst should extend this separation one step further: semantic analytical relationships and provenance links must remain a third/fourth species, never inferred merely from the first two.
