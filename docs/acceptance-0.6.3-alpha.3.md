# Catalyst 0.6.3-alpha.3 native acceptance — Working Picture

Alpha.3 is a UX-model acceptance build. It passes only if Catalyst is easier to recognize and navigate than alpha.2; build success alone is insufficient.

## Baseline integrity

1. Existing notes, evidence, tags, relationships, capabilities, and Map occurrence state survive the update.
2. Existing authored positions remain stable where they were explicitly placed.
3. Reader highlights and source jumps still work.
4. The Windows/taskbar icon uses the Catalyst mark rather than the historical boxed `E` placeholder.

## Three-second picture test

Open a nontrivial analysis and look at the right side for roughly three seconds before reading closely.

5. The surface should read as a composed analytical picture rather than graph paper or a collection of white text cards.
6. The current focus/Issue should be visually dominant without implying truth, confidence, or importance merely because it is selected.
7. Source-backed material should be visually distinguishable from abstract analytical constructs.
8. The source/assessed/open territories should help orientation without becoming heavy UI chrome.
9. Body text should not appear in ordinary Working Picture objects.

## Recognition-first portrayal

10. Abstract roles use Catalyst analytical glyphs rather than stock person/building/lightbulb icons.
11. Attached evidence in the observed territory appears as a clipped source-fragment landmark with a trace mark.
12. At overview zoom, labels largely disappear and structural form remains readable.
13. At normal working zoom, short identity labels return without body previews.
14. At closer zoom, source fragments/captions become richer, but full note content remains in inspection.
15. Semantic relationships are not globally drawn. Inspect/hover a related object and confirm its local semantic neighborhood appears.

## Navigation grammar

16. Single-click an object: it opens inspection without recentering the Working Picture.
17. Double-click or press Enter on the object: the Working Picture deliberately refocuses there.
18. Press Home or use the Home control: return to the Issue/root overview.
19. After refocusing, use the Working Picture Back control or Escape: return to the previous focus.
20. Opening an evidence source jumps to the exact PDF location and ordinary Reader/Context history remains reversible.
21. Routine use should not require repeated manual pan/zoom merely to find the current object or return home.

## Capture

22. Select text in the Reader. The capture UI should appear as a compact source fragment, not a paragraph-heavy card.
23. Capture actions are icon-led with tooltips/accessibility labels.
24. Creating a linked thought from the selection preserves source attachment automatically.

## Structure vs semantics

25. Tab creates a structural child branch.
26. Shift+Enter creates a sibling without stealing plain Enter from focus navigation.
27. Adding a semantic relationship does not rewrite branch hierarchy.
28. Collapsing a branch with relationships crossing the hidden boundary retains a continuation count/indicator.
29. Dragging an object is authored view state only; it does not change semantic relationships.

## Inspector

30. Opening the inspector must overlay the picture rather than causing the entire analysis to relayout.
31. Full note text, roles, confidence, relationships, methods, and source detail remain inspectable there according to active capabilities.

## Reject alpha.3 if

- the primary surface still feels like text cards connected by lines;
- custom glyphs merely decorate text rather than carrying recognition;
- source fragments are indistinguishable from ordinary notes;
- selection/refocus/open remain conflated;
- semantic edges again become globally visible clutter;
- opening inspection moves the analytical geography;
- Home/Back do not provide reliable orientation;
- the user must pilot the viewport to accomplish ordinary navigation.
